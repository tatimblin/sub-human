   - Keyset filter: keep a row when createdAt < c OR (createdAt == c AND id < i). In Postgres this becomes WHERE 
     (created_at, id) < ($1, $2) ORDER BY created_at DESC, id DESC LIMIT $3+1, backed by an index on (created_at 
     DESC, id DESC).
   - Response: 200 {items: [...], next_cursor: string|null}. Fetch limit+1 rows; next_cursor is null when there are
     no more rows.
   - New inserts while paging: they go at the head of the list, so a client walking the pages never sees duplicates
     or gaps. It also won't see the new rows until it starts again from the first page.
