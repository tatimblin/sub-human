⏺ Alice's Claude says it changed nothing. Here's how createTask in src/store.js picks ids:

  - Counter: let nextId = 1; at module scope (line 5), and createTask (line 7) assigns id: nextId++. Ids go 1, 2, 3… in
    the order tasks are inserted.
  - Lifetime: the counter goes back to 1 only when reset() runs (line 20). Ids aren't reused within a run, and since the
    store is in-memory they don't survive a restart.
  - Seed data: seed(n=237) goes through createTask, so seeded ids are 1–237. Every 3 tasks share a createdAt value (base
    + floor(i/3) minutes).
  - Paging: ids are unique and always increasing, but createdAt repeats. A cursor on createdAt alone would skip or
    repeat rows. Using (createdAt, id) or id alone would be stable. The file header says the store stands in for a
    Postgres table with about 4M rows taking about 30 inserts/sec.
