# sub-human

A Claude Code plugin for working together from separate sessions, on one machine or, over a link, from others. People join a room with `/sub-human` (as their git name; `/sub-human NAME` for another), invite another machine with `/sub-human invite`, and join one there with `/sub-human join HOST ROOM [PIN]` (`/sub-human help` lists every command). `@room` posts their exact words; `@claude` posts them and wakes the room's Claude. Claudes talk natively (`SendMessage`, addressed `NAME.CODE`; the room's Claude is `claude.CODE`). The room's Claude (member `claude`, a headless `claude --bg` job) keeps the shared task list and helps plan only when asked. User-facing docs: `plugin/sub-human/README.md`.

How it works (processes, store layout, lanes, consent, tasks, the cc contract): `docs/ARCHITECTURE.md`. Its tables are generated: run `npm run docs` after changing hooks.json, MCP tools, `lib/cc.ts` CONTRACT or a lib header.

## Layout

- `plugin/sub-human/`: the plugin, ESM `.ts` run by node with no build (`docs/ARCHITECTURE.md`, TypeScript); shared types in `lib/room/types.ts`, `lib/remote/types-*.ts`, `lib/types-app.ts`, `hooks/types.ts`, `mod/core/types.ts`, `lib/cli/types.ts`, `lib/commands/types.ts`, `mcp/types.ts`. `hooks/` (`run.ts <handler>`, the one node entry of every hook: it reads stdin once, loads only `handlers/<handler>.ts` and writes its one `Reply` (`types.ts`) at the edge (`reply.ts`); hooks.json keeps only the `/sub-human` expansion and SessionEnd, the module runs every other handler where it can act; `seat.ts` resolves the seat, `context.ts` the mechanics block, `launcher.ts` the row status launcher; `handlers/prompt.ts` runs every UserPromptSubmit handler in one process; only `at-room`, `consent` and `join` arm the seat key's signer), `lib/` (`commands/` every `/sub-human` command as a table of verbs (`index.ts` the router and its hidden rule for anything PIN-shaped, one file per verb; `handlers/join.ts` only renders the answer), `consent/` the consent hook's session side (`review.ts` the one pure reducer of a seat's review and note, with every line the model is told; `card.ts` the person's answer on any card the hooks built), `room/` the store behind the seam `store.ts` (`trust.ts` whether a person's line is theirs, from keys passed in; `rules.ts` the placement rules, pure; `log-io.ts` the log's bytes, in segments (`log.jsonl` the active one, sealed `log-NNNN.jsonl`) with `snapshot.json`, imported by `fs-store.ts` alone; `snapshot.ts` what a snapshot holds and whether a host's can be taken (pure); `fs-store.ts` FsRoomStore, the only module that names a room's files; `registry.ts` which store a code opens; `keys.ts`; `store-mirror.ts` a room hosted elsewhere, composing an FsRoomStore), validation, `consent.ts` (the one proposal fold and its queries, judged by the store's trust), `deliver.ts` (what an entry is for a seat: none, context, notice or wake), `render.ts` (lines, chat, join and leave notices) and `session.ts` (one document per seat: delivery cursor, shown notices, review, confirm, pick, holds, blocks) behind `room.ts`, plus the link registry (`links.ts`); `remote/` the wire: protocol, server, client, auth, the bridge, the link daemon (`link.ts`), transports, the joiner's link steps (`joining.ts`), and invites (`cpace.ts` the PAKE over the 4-digit PIN, `enroll.ts` its protocol and the ssh door, `admission.ts` the host's card); `vendor/noble/` the vendored, hash-pinned ristretto255 (`MANIFEST.json`; regenerate with `scripts/vendor-noble.js`, never edit); `seats.ts` entering, taking a seat (`take`) and leaving; `gc.ts` what a home stops keeping (closed rooms after 30 days, ended sessions' indexes and row maps; run from `take`); `tail.ts` the room tail the hooks module runs; `home.ts` store location; identity, `lock.ts`, `io.ts`, `config.ts` timings, `room-claude.ts` (the room's Claude: spawn/reap/watchdog), rows, tasks, proposals, `cc.ts` internals), `mcp/` (room server, hold, task tool), `agents/` (room-claude, room row, participant), `mod/` (the hooks module, entry `mod/register.ts`: guard, prompt gate, shims, delivery, rows; `mod/core` pure, and the owner of the constants and parsers node shares (lib/ and the handlers import them); `mod/test` wiring tests), `scripts/sub-human` (CLI and the tail: a JS shim at a frozen path, the body is `lib/cli/main.ts`), `skills/`, `statusline/`, `test/` (the node tests, ESM `.ts` named `*.node-test.ts` so `claude plugin test` never collects them; `test/helpers.ts` preloaded into each; `test/support/memory-store.ts` + `store-contract.node-test.ts` (four backends) keep the RoomStore seam honest, `store-bypass.node-test.ts` its import graph; `log-segments.node-test.ts` rotation, migration from one `log.jsonl`, crash recovery; `gc.node-test.ts` the sweep and the open-rooms index; `perf.node-test.ts` the 100k-entry budget (an @room append ≤ 50 ms, the status line ≤ 30 ms, and a fresh process over the segmented log; skipped under `SUB_HUMAN_TEST_THREAD_STORE` and with `SUB_HUMAN_SKIP_PERF=1`); `test/support/two-homes.ts` runs two homes on one machine for the remote tests).
- `scripts/`: demo and evidence tools. `demo.sh` drives the walkthrough in tmux, `demo-lib.js` holds its tmux and log helpers, `devbox.sh` the film's private sshd, `snap.js` captures panes, `checks.js` + `checks/*.js` hold the per-scene checks, `metrics.js` the run metrics, and `walkthrough.js` builds the HTML. `baselines.json` holds earlier runs, thresholds and prices. `lib/` has shared helpers: `paths.js` is the only place scripts import plugin paths (`pluginTest` for the scripts tests' use of plugin test support). `probe-cc.js` checks the internals list. The tests are in `scripts/test/`.
- `demo/app.pristine/`: the small app each demo seat gets a copy of.
- `docs/rebuild/`: the latest walkthrough (`walkthrough.html`, `checks.json`). `screens/` is generated and gitignored.
- `docs/internals/`: Claude Code internals we rely on, per version. `docs/archive/`: history, including the audit, mods, review, remote rooms and TypeScript plans (index in its README). There is no open work plan.

## Commands

- `npm test`: `npm run typecheck` (zero errors), plugin tests (`npm run test:plugin`: `node --test` over `plugin/sub-human/test/**/*.node-test.ts`) and script tests (`node --test`, no dependencies), then `npm run test:mods`.
- `npm run test:mods`: the hooks module's wiring tests (`mod/test/*.test.ts`) through `claude plugin test`; skipped without Claude Code 2.1.292+ or with hooks modules off.
- `npm run validate`: `claude plugin validate plugin/sub-human --strict`.
- `npm run typecheck`: `tsc` over the runtime (root `tsconfig.json`, `typings/claude-code` the committed Claude Code types; needs `npm ci`), then over the plugin's tests (`tsconfig.test.json`). The runtime and the plugin's tests are ESM `.ts` run by node 24.3+ type stripping; repo scripts and their tests (`scripts/test/`) stay CommonJS JS.
- `npm run test:remote-docker`: opt-in (needs Docker), the sub-human lab: `scripts/remote-docker/harness.js scenarios` runs the remote-rooms scenarios (P1 friends, P2 corporate via bastion and CONNECT proxy, P3 sleep, half-open, flap, slow link, 0.2.0 skew, security, handoff, 1.1 wss via tls-front and wss-resilience, login (join over the joiner's own ssh login); `tailscale` is opt-in with `TS_SERVE=1`) on a compose stack (project `sub-human-lab`: devbox, devbox-old, bastion, joiner-a, joiner-b, toxiproxy, corp-proxy, tls-front). Unbuilt features are PENDING; evidence in `/tmp/sub-human-lab-<time>/`. `scripts/remote-docker/README.md` has the topology. `npm run test:remote-docker:mac` is the older run with this Mac as the joiner (`/tmp/sub-human-remote-proof-<time>/`). `node scripts/remote-docker/harness.js up [--host-seat NAME] [--joiners alice,bob]` / `down` for real Claudes joining by hand (one `/tmp/sub-human-remote-manual/NAME.env` per joiner).
- `npm run test:thread-store`: the hook tests with every store call crossing `lib/remote/bridge.ts` to a worker thread.
- `npm run probe`: check every Claude Code internal listed in `lib/cc.ts` against the installed binary.
- `node scripts/check-version.js [BASE]`: fails when plugin files changed since the last version bump (or the newest tag, or BASE) without a newer `version` in plugin.json. Marketplace users get updates only when `version` changes, so bump it with every plugin change you release.
- `node --test --import ./plugin/sub-human/test/helpers.ts plugin/sub-human/test/X.node-test.ts` runs one plugin test file; `node --test scripts/test` runs only the script tests. `bash -n scripts/demo.sh` checks the demo's syntax.

## Demo

`scripts/demo.sh` runs scenes S1–S11 live, with real Claude sessions and real cost. It uses detached tmux sessions `sh-alice`, `sh-bob` (`--film`: `sh-tristan`, `sh-jess`) and `sh-claude` (`claude logs` of the room's Claude job), and `sh-carol` in S11. The home is `SUB_HUMAN_HOME=/tmp/sh-demo/home`, and the seats run in `/tmp/sh-demo/SEAT`. S11's carol joins from a second home, `/tmp/sh-demo/home2`, over the pipe link (alice's `/sub-human invite --pipe`, her card's Let in, carol's bare `/sub-human`); it runs before S10, which closes the room.

```
scripts/demo.sh [--windows] [--pause] [--only S6[,S7]] [--from S6] [--to S3] [--member-model MODEL] [--no-reset]
scripts/demo.sh --film [--take NAME]  # a trailer take -> trailer/capture/NAME/
scripts/demo.sh stop                  # kill the sh-* tmux sessions
node scripts/checks.js && node scripts/walkthrough.js
```

- A short run: `--only S1,S2,S4,S5,S9,S9b,S10` (a set with S1 starts fresh). `checks.js` skips the scenes not run (`screens/run.json`).
- A trailer take: `scripts/demo.sh --film [--take NAME]` runs the story only (S1–S5, S6b, S10) at 120×36 with prompts typed a key at a time. `scripts/capture.js` records every pane change and a marker per beat to `trailer/capture/NAME/capture.jsonl` + `run.json` (scene timings, checks verdict); `trailer/capture/fixture/` is a hand-made sample. In film mode the people are tristan (opens the room) and jess (joins) instead of alice and bob (`SEAT_A`/`SEAT_B` in demo.sh; tmux `sh-tristan`/`sh-jess`; capture session keys `tristan`, `jess`, `claude`); demo.sh writes the seats and the scripted words to `screens/run.json` (`seats`, `words`) and the checks read them there (default alice and bob). The seats are clones of one git repo (`/tmp/sh-demo/origin.git`), and S6b builds the agreed plan with real code on both sides: tristan's Claude the store (`listTasks` in `src/store.js` + `test/store-paging.test.js`), jess's Claude the HTTP handler (`src/server.js` + `test/server-paging.test.js`, written against the agreed `listTasks` after an Explore subagent reads the store, its row in her panel). tristan's Claude pushes and tells jess's; jess's pulls only then (the driver waits on the commits themselves), runs `npm test` and pushes; then both people pull and run `npm test`. jess is another machine: her seat has its own home (`/tmp/sh-demo/laptop/home`, `seat-env/jess`) and ssh config, and S2 joins her over real ssh to a private sshd on 127.0.0.1:2222 (`scripts/devbox.sh`, run as you, never root or `~/.ssh`; `SH_DEMO_SSH_PORT` for another port): tristan's `/sub-human invite` (`SUB_HUMAN_SSH_ADDR=devbox`) shows `/sub-human join devbox ROOM PIN`, the driver reads it off his pane, jess types it, tristan's card's Let in (`demo-lib admit-card`), jess's bare `/sub-human`; the sshd stops after S10 or an abort (`demo.sh stop` too; a resume starts it). Her checkout stays a local clone, and her Claude's `SendMessage` to tristan's is native on this Mac, not over the link. After jess joins (S2), each opens the room row in the agent panel (↓ onto it, Enter: the other shows inside it), then ↑ to main, Enter, and one ↑ back to the prompt. Film prompts are plain human words, no tool names. Checks in `checks/s06b-build.js` (each seat's commits stay in its own files, the handoff message precedes jess's pull). S6–S9, S9b and S11 never run in film mode and keep alice and bob.
- A timed-out `need` wait aborts the scene. The run stops and says how to resume with `--from SCENE`.
- `checks.js` exits 1 only when a **deterministic** check fails (log, chain, files, panes).
- **Behavioural** checks (model-call counts, wakes, noise) are compared against `baselines.json` thresholds and only warn.
- Never run the demo or touch `~/.sub-human` or live tmux sessions unless asked.

## Design rules

- **Never pin a model.** Not in agents, the room's Claude spawn, the demo or tests. The user's default applies, and `--member-model` is opt-in.
- **No writes to user settings files** (`settings.json`, `settings.local.json`) and no symlinks into `~/.claude`. The plugin uses its own home and the native task list.
- **The room's Claude takes no typed input.** A typed prompt is refused with a hint. People reach it with `@claude …` or through their Claude.
- **Keep the agent-panel rows.** A member's panel shows the room row with the members inside it. The room's Claude's panel lists every human.
- **Consent is native.** A proposal opens in the plan view, with the question card as fallback. Only the human's answer there (`via=human`) records agreement.
- **Unprescriptive.** Planning is optional, there is no required workflow, and the injected text covers mechanics only and stays small.
- **Internals are allowed if listed.** Each undocumented Claude Code behaviour goes in `lib/cc.ts` with the binary search string that proves it, and `npm run probe` verifies them. Notes go in `docs/internals/`.
- **Local git only.** No pushes and no remote PRs unless asked.
