# sub-human

A Claude Code plugin for working together from separate sessions, on one machine or, over a link, from others. People join a room with `/sub-human` (as their git name; `/sub-human NAME` for another), invite another machine with `/sub-human invite`, and join one there with the invite line `/sub-human join HOST ROOM SECRET`, then `/sub-human join PIN` when asked (`/sub-human help` lists every command). `@room` posts their exact words (`@claude …` is an ordinary prompt). Claudes talk natively (`SendMessage`, addressed `NAME.CODE`). A room has plans with versions, edited in each member's own plan mode and stored on the host under compare-and-swap (`lib/plans.ts`, `lib/consent/edit.ts`); sign-off is per version, in each person's plan view. The host applies task requests at once and writes them into the room session's native task list. The room session (member `claude`, `claude.CODE`, a headless `claude --bg` job) holds that list and the members' rows; it runs only a rows turn at start and per join, and never plans or answers. Any member's Claude does room upkeep when its person asks. User-facing docs: `plugin/sub-human/README.md`.

How it works (processes, store layout, lanes, consent, tasks, the cc contract): `docs/ARCHITECTURE.md`. Its tables are generated: run `npm run docs` after changing hooks.json, MCP tools, `lib/cc/contract.json` or a lib header.

## Commands

- `npm test`: `npm run typecheck` (zero errors), plugin tests (`npm run test:plugin`: `node --test` over `plugin/sub-human/test/**/*.node-test.ts`) and script tests (`node --test`, no dependencies), then `npm run test:mods`.
- `npm run test:mods`: the hooks module's wiring tests (`mod/test/*.test.ts`) through `claude plugin test`; skipped without Claude Code 2.1.292+ or with hooks modules off.
- `npm run lint`: oxlint with type-aware rules (`.oxlintrc.json`), then the type-escape ratchet. On the plugin and the scripts `no-explicit-any`, `no-non-null-assertion`, the `no-unsafe-*` family, `no-floating-promises` (node:test's `test`/`describe` allow-listed), `no-misused-promises`, `only-throw-error`, `consistent-type-imports` and `no-unnecessary-type-assertion` are errors (a reasoned `// oxlint-disable-next-line rule -- why` only where no narrowing can say it; none in tests); `no-unsafe-type-assertion`, `prefer-nullish-coalescing` and the correctness category warn. The ratchet: explicit `any`, `as` casts and non-null `!` per directory may not rise above `scripts/ts-ratchet.json` (it is what caps casts); when you remove some, `node scripts/ts-ratchet.ts --update` lowers the file. Runtime code has no `!` (the ratchet holds it at 0); tests narrow with `test/support/must.ts` `must(v, what)` or `assert.ok`.
- `npm run validate`: `claude plugin validate plugin/sub-human --strict`.
- `npm run typecheck`: `tsc` over the whole plugin (root `tsconfig.json`, strict plus `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess`: runtime, tests, `mod/test`, the two `.js` files; `typings/claude-code*` the committed Claude Code types; needs `npm ci`), then the runtime alone (`tsconfig.runtime.json`, with `isolatedDeclarations`: every export states its type), then the repo scripts (`scripts/tsconfig.json`), then `scripts/sub-human` (`scripts/typecheck-shim.ts`). The runtime, the plugin's tests and the repo scripts and their tests (`scripts/test/`) are ESM `.ts` run by node 24.3+ type stripping; a module loaded at first use is `lib/io.ts` `lazy<typeof XMod>(import.meta.url, './x.ts')` beside `import type * as XMod from './x.ts'` (`scripts/test/lazy.test.ts` checks the pair; no `createRequire` elsewhere), and a cheap hook's module set must not grow; `demo/app.pristine/` stays JS (the sample app demo seats edit).
- `npm run typings`: copy the declarations Claude Code writes beside the hooks module (`plugin/sub-human/.claude-plugin/types/claude-code{,-tools,-mcp}`, gitignored; an interactive `claude --plugin-dir plugin/sub-human` session writes them) into `typings/`. Run it after a Claude Code update; `npm run probe` fails while `typings/claude-code`'s "Written by Claude Code X" line is not `contract.json` `probed`.
- `npm run test:remote-docker`: opt-in (needs Docker), the sub-human lab: `scripts/remote-docker/harness.ts scenarios` runs the remote-rooms scenarios (P1 friends, P3 sleep, half-open, flap, slow link, skew against the previous release (`LAB_OLD_REF`, 0.5.0-beta.16: protocol 3 against 4, refused with the update message), security, 1.1 wss via tls-front (the lab-only `SUB_HUMAN_WEB_FRONT`) and wss-resilience, login (join over the joiner's own ssh login), short; `tailscale` is opt-in with `TS_SERVE=1`) on a compose stack (project `sub-human-lab`: devbox, devbox-old, joiner-a, joiner-b, toxiproxy, tls-front). Unbuilt features are PENDING; evidence in `/tmp/sub-human-lab-<time>/`. `scripts/remote-docker/README.md` has the topology. `node scripts/remote-docker/harness.ts up [--host-seat NAME] [--joiners alice,bob]` / `down` for real Claudes joining by hand (one `/tmp/sub-human-remote-manual/NAME.env` per joiner).
- `npm run probe`: check every Claude Code internal listed in `lib/cc/contract.json` against the installed binary (`scripts/probe-cc.ts` reads the JSON; the matcher is `lib/cc/contract.ts` probe), and that the typings snapshot was written by the probed version (`--no-typings` skips that).
- `npm run canary [-- latest|next|stable|X.Y.Z] [--config-dir DIR]`: the early warning (`scripts/canary.ts`; CI runs it nightly on latest and next). It installs `@anthropic-ai/claude-code@TAG` into `<tmpdir>/sub-human-canary/TAG` (`npm i --prefix`, never global), takes the native binary from the platform's optional package (`@anthropic-ai/claude-code-<platform>/claude`), and runs the probe (`--no-typings`, failures grouped by each entry's `feature`, else `section`), `test:mods` (its modules-off skip counts as a failure) and `plugin validate --strict` against it, with a fresh `CLAUDE_CONFIG_DIR` under the prefix (those commands write `.claude.json`; a fresh config has modules on) unless `--config-dir` names one. Summary in `scripts/canary/last.json` (gitignored); exit 1 on any failure.
- `node scripts/check-version.ts [BASE]`: fails when plugin files changed since the last version bump (or the newest tag, or BASE) without a newer `version` in plugin.json. Marketplace users get updates only when `version` changes, so bump it with every plugin change you release.
- `node --test --import ./plugin/sub-human/test/helpers.ts plugin/sub-human/test/X.node-test.ts` runs one plugin test file; `npm run test:scripts` (`node --test 'scripts/test/**/*.test.ts'`) runs only the script tests. `bash -n scripts/demo.sh` checks the demo's syntax.

## Demo

`scripts/demo.sh` runs scenes S1–S11 live, with real Claude sessions and real cost. It uses detached tmux sessions `sh-alice`, `sh-bob` (`--film`: `sh-tristan`, `sh-jess`) and `sh-claude` (`claude logs` of the room session's job), and `sh-carol` in S11. The home is `SUB_HUMAN_HOME=/tmp/sh-demo/home`, and the seats run in `/tmp/sh-demo/SEAT`. S11's carol joins from a second home, `/tmp/sh-demo/home2`, over the pipe link (alice's `/sub-human invite --pipe`, carol's line and then her PIN, alice's card's Let in, carol's bare `/sub-human`); it runs before S10, which closes the room. S4: B's own Claude writes room plan v1 in plan mode (the store's receipt, no dialog) and asks both to sign off; S5: A objects with a note, both Claudes edit from v1 at once (the second meets a conflict and reconciles into v3), both sign off on it. Checks in `checks/s04-plan.ts`, `checks/s05-consent.ts`.

```
scripts/demo.sh [--windows] [--pause] [--only S6[,S7]] [--from S6] [--to S3] [--member-model MODEL] [--no-reset]
scripts/demo.sh --film [--take NAME]  # a trailer take -> trailer/capture/NAME/
scripts/demo.sh stop                  # kill the sh-* tmux sessions
node scripts/checks.ts && node scripts/walkthrough.ts
```

- A short run: `--only S1,S2,S4,S5,S9,S9b,S10` (a set with S1 starts fresh). `checks.ts` skips the scenes not run (`screens/run.json`).
- A trailer take: `scripts/demo.sh --film [--take NAME]` runs the story only (S1–S5, S6b, S10) at 120×36 with prompts typed a key at a time. `scripts/capture.ts` records every pane change and a marker per beat to `trailer/capture/NAME/capture.jsonl` + `run.json` (scene timings, checks verdict); `trailer/capture/fixture/` is a hand-made sample. In film mode the people are tristan (opens the room) and jess (joins) instead of alice and bob (`SEAT_A`/`SEAT_B` in demo.sh; tmux `sh-tristan`/`sh-jess`; capture session keys `tristan`, `jess`, `claude`); demo.sh writes the seats and the scripted words to `screens/run.json` (`seats`, `words`) and the checks read them there (default alice and bob). The seats are clones of one git repo (`/tmp/sh-demo/origin.git`), and S6b builds the agreed plan with real code on both sides: tristan's Claude the store (`listTasks` in `src/store.js` + `test/store-paging.test.js`), jess's Claude the HTTP handler (`src/server.js` + `test/server-paging.test.js`, written against the agreed `listTasks` after an Explore subagent reads the store, its row in her panel). tristan's Claude pushes and tells jess's; jess's pulls only then (the driver waits on the commits themselves), runs `npm test` and pushes; then both people pull and run `npm test`. jess is another machine: her seat has its own home (`/tmp/sh-demo/laptop/home`, `seat-env/jess`) and ssh config, and S2 joins her over real ssh to a private sshd on 127.0.0.1:2222 (`scripts/devbox.sh`, run as you, never root or `~/.ssh`; `SH_DEMO_SSH_PORT` for another port): jess has her own ssh login to it (devbox.sh puts her key in its authorized_keys and its host key in her known_hosts); tristan's `/sub-human invite` (`SUB_HUMAN_SSH_ADDR=devbox`) shows `/sub-human join devbox ROOM SECRET --home …` and the PIN apart, the driver reads both off his pane (`demo-lib join-line`, `join-pin`), jess types the line, then `/sub-human join PIN` when her machine asks, tristan's card's Let in (`demo-lib admit-card`), jess's bare `/sub-human`; the sshd stops after S10 or an abort (`demo.sh stop` too; a resume starts it). Her checkout stays a local clone, and her Claude's `SendMessage` to tristan's is native on this Mac, not over the link. After jess joins (S2), each opens the room row in the agent panel (↓ onto it, Enter: the other shows inside it), then ↑ to main, Enter, and one ↑ back to the prompt. Film prompts are plain human words, no tool names. Checks in `checks/s06b-build.ts` (each seat's commits stay in its own files, the handoff message precedes jess's pull). S6–S9, S9b and S11 never run in film mode and keep alice and bob.
- A timed-out `need` wait aborts the scene. The run stops and says how to resume with `--from SCENE`.
- `checks.ts` exits 1 only when a **deterministic** check fails (log, chain, files, panes).
- **Behavioural** checks (model-call counts, wakes, noise) are compared against `baselines.json` thresholds and only warn.
- Never run the demo or touch `~/.sub-human` or live tmux sessions unless asked.

## Design rules

- **Never pin a model.** Not in agents, the room session's spawn, the demo or tests. The user's default applies, and `--member-model` is opt-in.
- **No writes to user settings files** (`settings.json`, `settings.local.json`) and no symlinks into `~/.claude`. The plugin uses its own home and the native task list.
- **The room's Claude takes no typed input.** The room session (member `claude`) refuses a typed prompt with a hint, refuses Claudes' messages and reads nothing but joins (its rows turn).
- **Keep the agent-panel rows.** A member's panel shows the room row with the members inside it. The room session's panel lists every human.
- **Consent is native.** A proposal opens in the plan view, with the question card as fallback. Only the human's answer there (`via=human`) records agreement.
- **Unprescriptive.** Planning is optional, there is no required workflow, and the injected text covers mechanics only and stays small.
- **Internals are allowed if listed.** Each undocumented Claude Code behaviour goes in `lib/cc/contract.json` with the binary search string that proves it (and a `@cc` tag on the `lib/cc/*.ts` export that relies on it), and `npm run probe` verifies them. Notes go in `docs/internals/`.
- **Local git only.** No pushes and no remote PRs unless asked.
